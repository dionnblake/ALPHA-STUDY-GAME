# AI Study Game: project guide

Read this before changing code or content. The app is a local Windows 11 study game for learning AI, Google AI, prompt engineering, and GenAI on Google Cloud material. The user values useful learning material over volume. Do not add filler questions.

## Stack

- Desktop app: Tauri + React + TypeScript + Vite.
- Router: `HashRouter` in `src/components/AppShell.tsx`.
- Database: local SQLite through `@tauri-apps/plugin-sql`.
- Main DB file: `ai_study_game.db`.
- Question banks live in `public/questions/`.
- Seed/import code lives in `src/services/seedingService.ts`.
- Quiz state and answer scoring live in `src/hooks/useQuiz.ts`.

- `src/services/seedingService.ts`: loads JSON files and normalizes rows into SQLite.

## Question bank contract

Preferred JSON fields:

- `uid` and `id`
- `questionText`
- `questionType`: usually `multiple_choice`
- `options`: exactly 4 options unless intentionally using another supported type
- `correctAnswer`: exact text matching one option
- `option_a` through `option_d`: mirror `options`
- `category`
- `difficulty`: usually `adaptive`
- `tags`: must include the track tag
- `explanation`
- `remediationNotes`
- `learningObjective`

The seed service converts this into DB columns:

- `question_text`
- `option_a` through `option_i`
- `correct_answer`
- `category`
- `difficulty`
- `tags`
- `domain_id`
- `question_type`
- `scenario`

## Non-negotiable question quality rules

Do not add bullshit questions. A question should teach or test a real concept from the source material.

Every question must pass these checks:

- The correct answer must not be guessable by length.
- The correct answer must not be consistently more detailed than the distractors.
- Distractors must be plausible misunderstandings or neighboring concepts, not silly throwaways.
- Never use options like "all of the above", "none of the above", "always", or "never" unless the source truly supports it.
- Do not leak the answer in the stem.
- Do not create trick questions unless the source material makes the distinction important.
- Prefer scenario, usage, pitfall, and production-impact questions over definition-only trivia.
- Explanations must explain why the answer is correct, not merely restate it.
- Remediation notes should tell the learner how to remember or distinguish the concept.

Length-bias gate:

- For a bank of 200 multiple-choice questions, the correct answer should be the longest option in no more than 40% of questions.
- Better target: under 30%.
- If it is above the gate, fix the bank before shipping.

For the `GenAI on Google Cloud` bank, the current target is much stricter: correct answer longest should stay near 5 of 200 unless there is a good reason.

## Required validation after question edits

Run a validation command after changing any bank. At minimum:

```bash
node -e "const fs=require('fs'); const q=JSON.parse(fs.readFileSync('public/questions/genai_on_google_cloud_questions.json','utf8')); let longest=0; const problems=[]; const ids=new Set(); const stems=new Set(); for (const x of q){ if(ids.has(x.uid)) problems.push('duplicate uid '+x.uid); ids.add(x.uid); if(stems.has(x.questionText)) problems.push('duplicate stem '+x.questionText); stems.add(x.questionText); if(!Array.isArray(x.options)||x.options.length!==4) problems.push('bad option count '+x.uid); if(!x.options.includes(x.correctAnswer)) problems.push('answer missing '+x.uid); if(new Set(x.options).size!==x.options.length) problems.push('duplicate option '+x.uid); if(x.correctAnswer.length===Math.max(...x.options.map(o=>o.length))) longest++; } console.log({count:q.length,longest,problems:problems.slice(0,10)}); if(problems.length||longest/q.length>0.4) process.exit(1);"
```

Then run:

```bash
npm run build
```

Known build warnings about large chunks and `database.ts` dynamic/static import overlap already exist. They are not blockers unless a task specifically asks to fix build performance.

## DB reseeding rule

If a question bank changes and existing users need the new content, bump the `db_version` gate in `src/services/database.ts`.

Example:

```ts
if (currentVersion < 18) {
  await db.execute("DELETE FROM questions");
  await db.execute("INSERT OR REPLACE INTO settings (key, value) VALUES ('db_version', '18')");
}
```

Without this, an already-seeded local database can keep old questions.

## UI behavior notes

- Quiz answer cards should be real buttons, not clickable `div`s. This avoids selection/submit issues in the WebView.
- Submit unlocks when `selectedLetter` or `selectedLetters` is set in `useQuiz.ts`.
- If users cannot submit, inspect selection state before blaming the question bank.

## Development habits

- Keep changes surgical.
- Do not reformat unrelated files.
- Use existing app patterns before inventing new structure.
- When adding a new track, update:
  - `public/questions/...`
  - `src/services/seedingService.ts`
  - `src/services/analyticsService.ts`
  - `src/components/Sidebar.tsx`
  - `src/services/examBlueprint.ts`
  - `src/services/database.ts` if reseeding is needed
- Run `npm run build` before calling a change done.

## User preference

The user is building this to learn. Prioritize accuracy, useful distinctions, and study value. More questions are only better when they are genuinely educational.
